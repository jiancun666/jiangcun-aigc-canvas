## 2026-09-29 同序号并发结果可能互相覆盖
- 状态：待验证
- 已确认：`saveAssets` 对每个结果先 `INSERT IGNORE`，再按 `(step_run_id, output_index)` 查询并无条件 `updateById(asset)`。在同一任务被错误地并发处理且同一序号对应不同供应商结果时，后到事务可能覆盖先到记录；正常租约应避免该场景，但尚无数据库并发测试证明。
- 已完成：静态审计写入顺序与租约/行锁逻辑。
- 已验证：现有单测只验证重复同结果，不覆盖不同结果并发；未执行并发集成测试。

- 2026-09-28：图片生成成功当前直接写入 `asset` 和 `aigc_generated_asset`，与截图中手动“保存到资产”的语义冲突，需先确定目标行为。
- 2026-09-28：`sql/aigc_canvas.sql` 的 `t_asset` 不支持工作区隔离，与当前 Java `asset` 映射不一致；该旧表删除标记 0=未删除，而新表约定 1=正常，不能混用。
- 2026-09-28：团队写权限辅助实现读取 `workspaceRole` 请求头，但目前看到的网关未注入该头；资产模块写/删权限不应依赖此头，需用已校验身份与数据库成员角色判断。
- 2026-09-28：暂未发现工作区切换接口；JWT 只表示当前工作区，个人/团队历史同时展示或切换时需要明确会话切换规则。
- 2026-09-28：`team_member.role` 的数据库约束仅允许 OWNER/MEMBER；若“团队管理员”不是 OWNER，需先确定角色扩展及鉴权来源。
- 2026-09-28：历史允许产出被删除而保存资产要求保留；若两者共享唯一物理文件或仅引用外部临时 URL，删除历史产出会破坏资产保证。需确定保存时的持久化、引用及清理规则。
- 2026-09-28：“所有生成历史”的范围尚不明确（当前工作区、本人跨空间、或团队成员可见的记录）；查询不能绕过现有工作区鉴权。画布引用已失效历史产出时也需明确禁用或提示。
- 2026-09-28：生成任务有 `(workspace_id, client_request_id)` 唯一键，但 `aigc_generated_asset` 只有随机 `asset_no` 唯一；worker 租约到期或结果重试可能重复插入同一产出。单任务可多产出，建议实施时为每个结果建立稳定产出序号/供应商产出 ID 与数据库唯一约束。
- 2026-09-28：`aigc_generated_asset.asset_id` 是单值；若同一历史产出可同时保存进个人及团队资产库，单字段无法表达多个目标资产关联，需先确定保存语义再定关联模型。
- 2026-09-28：当前创建图片任务校验模型为 IMAGE，但未看到画布 node_type 与 model_type 一致性校验；历史分类若依据节点快照，创建时必须校验一致。ModelProvider 仅支持 ImageRequest，ProviderAsset 缺视频/音频时长、缩略图等；Ark 图片同步返回伪 provider_request_id 且 poll 不支持，因此历史不能仅依赖后续供应商轮询。
- 2026-09-28：新增 `(step_run_id, output_index)` 唯一键后，MySQL 对任一 NULL 的组合仍允许重复；现有生成写入代码尚未设置 output_index，必须在接入历史幂等逻辑时保证模型生成记录两个字段均非空。迁移回填按时间和 ID 保存旧记录，不自动合并既有重复历史。
- 2026-09-28：关键环境偏差：现有 `aigc_canvas` 数据库与 Java/`sql/canvases.sql` 目标模型不一致，导致 `20260928_generated_asset_output_index.sql` 第一条 ALTER 即报 1146；不能在 `t_asset` 上直接补幂等键来替代历史表。先确定目标数据库模型后再编写适用的建表/迁移脚本。
- 2026-09-28：`sql/semple_aigc_canvas.sql` 是包含 DROP/CREATE 的初始化脚本，已恢复原内容；已有数据库增量升级应执行单独的 `sql/semple_aigc_canvas_output_index.sql`，并先确认目标表实际存在。
- 2026-09-28：本轮代码依赖目标库已存在 `aigc_generated_asset.output_index` 及 `uk_generated_asset_step_output`；本机无 Maven，新增单测和 Java 编译未执行。当前 ProviderAsset 标准协议没有独立供应商产出 ID，幂等键使用步骤产出序号。
- 2026-09-28：历史查询接口的参考图依赖生成请求配置中的 `referenceImages`/`referenceImage`/`reference_images` 键；当前数据库没有独立参考素材字段或关联表，未定义键时 VO 返回空，不能保证旧数据可还原参考图。
- 2026-09-29：通用历史接口当前返回扁平分页列表，不包含截图顶部各媒体 Tab 的全量数量；如前端必须展示数量，需要另加按 `asset_type` 聚合的统计接口，不能用当前筛选页 `total` 冒充全部类型数量。
